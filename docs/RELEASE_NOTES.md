# 发布说明 — SDK 0.2.0 / Jetson Orin NX

发布日期：2026-10-20。
示例更新：2026-10-26，新增自动识别与通信预检查；SDK wheel 版本及内容不变。

## 支持与验证

目标平台为 ARM64 / Ubuntu 22.04。验证设备为 Jetson Orin NX 8GB、
Ubuntu 22.04.5、L4T R36.4.3、内核 `5.15.148-tegra`。

| Python | 实测版本 | 软件验证 | 示例 1～3 真机/GUI |
| --- | --- | --- | --- |
| 3.8 | 3.8.20 | 通过 | 未实测 |
| 3.9 | 3.9.25 | 通过 | 未实测 |
| 3.10（默认） | 3.10.12 | 通过 | 通过 |
| 3.11 | 3.11.17 | 通过 | 未实测 |

软件检查包含四个核心的 ELF/ABI/安装审计、核心源码排除、URDF/网格加载、
19 自由度 FK、CVXPY 约束 QP、SDK 单步数值 IK、示例 4 参数帮助及无硬件 mock 回归。
这些软件检查不发送硬件命令，与 Python 3.10 已完成的示例 1～3 真机/GUI 验证分开记录。
3.10 的真机/GUI 结果不能代替其他 Python 版本的实测。

SDK 单步 IK 测试的误差从 `0.0131600077833` 降至约 `6.30777289718e-05`，
固定头部关节未改变。该结果不是实际机器人末端精度测量。

## 发布内容

- 四份 `linux_aarch64` wheel：cp38、cp39、cp310、cp311，SDK 版本均为 0.2.0。
- 每个 Python 小版本独立的依赖版本清单及安装说明。
- Python 3.8 补充 ECOS 2.0.14 ARM64 wheel、对应源码归档和原许可证。
- PCAN-USB 的 netdev 内核模块、对应上游源码、许可证及恢复/构建说明。
- 原有 D1 示例、模型、辅助工具和选配功能参考。
- 不访问硬件的安装与 IK 检查工具，及 `SHA256SUMS` 文件完整性清单。

## 设备默认值

示例 1～10 的硬件配置现默认使用 `auto`；示例 0 是纯仿真。
头臂、外骨骼、手套按 USB 身份及协议响应识别，PCAN 和相机按 USB 身份识别。
原验证设备的映射为 `can1`、`/dev/ttyACM0` 和 SunplusIT SPCA2100 相机的 by-id index0 路径，
不作为其他机器的固定编号。手动指定路径/接口仍受支持，运动示例会继续验证通信。

本次改动增加了控制器初始化前的 CAN 应答与相机取帧检查、带角色/端口/阶段的报错、
候选设备排除原因和舵机故障状态区分。CAN 须事先配置为 UP、1 Mbps，预检查不配置总线。
CAN/相机故障汇总后会跳过串口探测，并列出未检查项。
示例 7/8 启动中途失败会清理已打开的设备；示例 8 异常退出时不额外回零或张手，运行异常继续向调用方抛出。
开发回归测试保留在维护环境，客户发行目录仅保留安装检查和设备诊断工具。
新增的自动识别与预检查仅完成无硬件回归，尚未进行 NX 真机/GUI 复验；
上文 Python 3.10 的真机记录属于原固定端口版本。

## 已知限制

1. Python 3.10 的示例 1～3 已通过真机/GUI 验证；3.8、3.9、3.11 的真机/GUI 尚未实测。
   示例 0、4～10、选配工具和仿真功能尚未测试，不属于本次已验收范围。
2. SDK 支持范围为 CPython `>=3.8,<3.12`；不是 abi3，不包含 x86/PyPy/3.12+ 安装包。
3. 可选 dex-retargeting 0.4.0 的声明范围为 `>=3.7,<3.11`，独立于 SDK 支持矩阵；
   该库及其 Torch/MediaPipe/仿真相关依赖未完成 NX 适配验收。
4. 附带 PCAN 模块只在当前匹配内核上验证，没有开机自动加载或 CAN 自动配置。
5. 相机示例是 USB/V4L2 路径，需要实际 USB 连接；窗口显示需要桌面会话。
6. 本包不是完整离线仓库，运行依赖仍需联网或客户受控镜像安装。
7. Cython 二进制核心是源码保护形式，不是密码学加密、许可绑定或防逆向保证。
8. 其他 JetPack、Linux/glibc、内核或设备组合需要重新验收。
